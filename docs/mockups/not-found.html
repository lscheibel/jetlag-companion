Four ways to say nothing is here

The screen behind root.tsx's ErrorBoundary is still the React Router starter: a centred <h1>404</h1> in the browser's default face, on no background, with no way out. It is the one screen in the app that has never been designed. These are four takes on it, drawn in the shipped role tokens, both themes live.

01

End of the line

The most literal reading of the app's own vernacular. A dead URL is a stop that is not on the network, so the screen draws the network: a U-Bahn line with four stations, then the track thinning to a marching dashed stub and a hollow ring where the stop you asked for would have been. The number 404 never appears — the diagram carries the whole message, and the words underneath are the two causes in plain language.

Reads as
Berlin U-Bahn line diagram, in transit-u blue
Motion
Marching dash on the stub (zl-march, already in motion.css) and a breathing ring
New assets
One inline SVG, about 12 elements. Nothing else
Back control
Header caret and a quiet second action — this screen is not a step in a flow, so the caret alone is a guess

What it costs: the metaphor is doing the explaining, and a player who does not read the diagram as a transit line gets a headline that could mean the game ended. The body copy has to carry more weight than it does in the other three.

02

Departure board

Azeret Mono doing all the work. The requested address is a service that has been cancelled, and the way out is the next departure sitting on the row below it, green and marked NOW. This is the one proposal that wears the number — but as a service code on a signage plate, which is how a transit system would actually print it. It stops being a stack trace leaking into the UI and becomes something a player could read out over the phone.

Reads as
Split-flap departure board; surface-sunken panel, hairline rules
Motion
One flap on arrival — each character of the dead address rotates in on a 60 ms stagger, then stops. No loop
New assets
None. A grid, three rows, and the existing plate treatment
Colour
The only screen where danger and live appear together, and the contrast is the message

What it costs: the most personality and the least clarity. A board is a thing you scan for your own row, and here every row is the app talking about itself. It is also the hardest to make work at 320 px with a long address — the destination cell has to ellipsise, which is exactly the character the player would want to see. "Take the next one" is charming until somebody reads it as rejoining a game.

03

Off the map

The app is a map app, so the empty screen is an empty map: real map-land, blocks, water and a park, with five stations on it — then the whole thing under the map-eliminated scrim the seeker map already uses for ruled-out ground, and a slowly rotating dashed ring around a question mark where you tried to go. It borrows the game's own visual grammar for "searched here, nothing".

Reads as
The seeker map with everything ruled out
Motion
An 18 s rotation and a 3.2 s pulse ring — both already tokens (--dur-sweep, --dur-pulse)
New assets
One decorative map SVG, roughly 18 elements. It is drawn, not a live MapLibre canvas — no tiles, no worker, works offline
Strength
The only proposal that looks like this app rather than like transit signage in general
Copy
  • HeadThere is no such place.
  • BodyThe address you opened does not point anywhere in the app. Check the link you were sent, or start again from the front.
  • ActionBack to the start

What it costs: the metaphor can lie. "Place", "area" and the eliminated scrim all mean specific things during a round, and a player who hits this screen mid-game may read it as the hider is not here rather than this URL is wrong. The copy above deliberately avoids the words game area and zone for that reason — if this direction wins, that constraint has to hold.

04

The plate you already have

No new idea at all — deliberately. This is setup/unknown-code.tsx with the code swapped for a path: the same Screen / ScreenHeader / ScreenActions frame, the same Surface quoting what you asked for, the same InlineNotice, the same beacon on the one action. A player who mistypes a join code and a player who opens a dead link land on the same screen twice, which is the argument for it.

Reads as
An ordinary Zero Lag screen. That is the point
Motion
Body enter, action sheen. Nothing bespoke
New assets
Zero. Shipped components only, about 40 lines
Degrades
The only one that survives the non-404 branch — a thrown error keeps the frame and swaps the two lines of copy

What it costs: it is forgettable, and this is a screen people screenshot. It also spends its second action on Join by code, which is a real guess about why somebody is here — worth it if most dead links are mistyped invitations, wrong if most are stale links to finished games.

Whichever wins

Four questions none of the four settles

One component, two jobs

The thrown-error branch

ErrorBoundary catches a 404 and anything that throws, plus a dev stack trace. Three of these are designed for the 404 only. Either the boundary splits in two, or the winning direction needs a second state — and 01, 02 and 03 all have art that would be a lie over a crash.

Where back goes

Two exits, not one

The header caret is history, which on a cold-opened bad link is the page before the app. Every proposal therefore also offers Back to the start, an explicit navigate("/"). On a screen reached by accident, one exit is not enough.

A rule already broken

Saying "404" at all

The direction is no technical vocabulary in user-facing text. 01, 03 and 04 drop the number; 02 keeps it as a printed service code. Keeping it has one real benefit — it is the word a player would use when reporting the problem.

Not this screen's job

Bad codes are handled

UnknownCode already catches a join code that resolves to nothing, with the code quoted and a retry. This screen only ever sees an address that is not a route — which is why 04's Join by code action is a question and not a given.
