One sheet is doing two different jobs

The tracking sheet asks a player to install a second app, during a game, for a benefit they cannot see yet — and then it asks the same player, an hour later, one much smaller question: is it still working? Today both live in one stack of eleven things with no order and no ending. Three proposals, each separating those two jobs a different way: a checklist that visibly completes, a wizard that matches every other setup path in the app, and a connection card that keeps the sheet and inverts what it leads with. Every one of them keeps m15-spec §6: optional first, one app at a time, a per-app address, no QR.

·

And underneath all six: two jobs, one surface

Setting this up is a sequence with an end. Checking on it is a glance. The screen that has to do both is currently the one that does neither — a returning player gets the full install walkthrough to find a timestamp, and a first-timer gets a status line about a thing they have not configured yet.

Three ways out

A task, a flow, or an object

The three differ in what they think the screen is. A treats it as a task with an order and an end. B treats it as a flow, which is what every other setup path in this app already is. C treats it as a thing you check on, and puts the setup material underneath.

All three: the token is truncated on screen and whole on the clipboard, the address carries the app's own placeholders, the install link is a control rather than centred underlined text, and turning it off is not in the main stack. Details in the last band.

All three

Six changes that are not about the layout

These hold whichever shape wins. Two of them are small enough to land on their own before a shape is picked.

Proposed

The token is truncated on screen, whole on the clipboard

Forty characters of entropy is the biggest element on the sheet and the only part nobody reads. Enough of it to tell two addresses apart, and no more — which also stops the screen printing a credential at full size in a crowded carriage.

Proposed

Nothing is issued behind a button that shows nothing

Today "Set up background tracking" POSTs a token and re-renders into a wall of instructions. In all three the button that issues names what it produces — Get the address, or the step that needs it — so the tap has a visible result.

Settled elsewhere

Turning it off leaves the main stack

It revokes a URL already pasted into another app, and it currently sits one tone away from Copy. Behind the ⋯, in a sheet, with a red button — exactly the shape the lobby settled for leaving a game.

Proposed

The install link is a control

A centred underlined line is the only one of its kind in the kit. It becomes a row with the app's own label — "Get GPSLogger on F-Droid" — because m15-spec §6 already refuses to infer a store from the platform.

Proposed

The loopback warning attaches to the address

It is about that string, so it sits with it rather than floating near the top of the sheet. It is also the one thing on this screen every developer sees on every run, so it should not be the thing that pushes the address off the fold.

Needs your call

Does the phone remember which app it uses?

A device picks its tracker once and keeps it for good. Storing that in localStorage would mean a returning player never re-picks — the same argument as the briefing-seen flag: which app you use is not game state. It would also let the status screen say OsmAnd without asking.

Needs your call

Three things I could not settle from the spec

Question

Sheet, or screen?

B is the only one that leaves the sheet, and it is the only one that matches the house rule about flows. But the locate control opens a sheet, and this would be a sheet handing off to a full screen over a live map, mid-round. A and C keep the nesting; B trades it for the frame every other setup path uses.

Question

Does "waiting" deserve the primary slot?

B gives the wait an entire screen because that is what makes the feature trustworthy. A gives it a step. C gives it a word in the hero. The more room it gets, the more the screen is honest about the fact that the real work happens in another app — and the longer the player stares at a map they could be using.

Question

Should the position sheet carry the age, or the link?

The position sheet already reports the tracker as a source with its own age. If it does that well, this screen's hero is a second opinion on the same fact, and C's case weakens while A's and B's — which are about doing the setup — get stronger. Worth deciding before the shape.
